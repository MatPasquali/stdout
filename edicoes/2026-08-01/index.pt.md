### [Beacon: Knowing When and How to Perform Agentic Visual Reasoning](https://arxiv.org/abs/2607.28595v1)
`arXiv`

Pesquisadores publicaram um trabalho intitulado Beacon, que visa aprimorar a taxa de sucesso de modelos de linguagem multimodais grandes (MLLMs) em tarefas complexas, focando em dois aspectos principais: Adaptatividade de Modo (MA) e Efeito de Ferramenta (TE), que permitem que os MLLMs reconheçam quando as ferramentas são necessárias e usem-nas de forma eficaz, melhorando o desempenho em problemas desafiadores. Isso é importante porque os MLLMs podem ser ineficientes se não souberem quando e como usar as ferramentas adequadamente. A Adaptatividade de Modo caracteriza a capacidade do MLLM de reconhecer a necessidade de ferramentas e invocá-las conforme necessário. O Efeito de Ferramenta caracteriza o impacto real do uso de ferramentas, que deve estender as capacidades do modelo em problemas que não podem ser resolvidos apenas com raciocínio baseado em texto.

### [Change2Task: From Repository Changes to Executable Coding Agent Tasks and Environments](https://arxiv.org/abs/2607.28591v1)
`arXiv`

Pesquisadores desenvolveram o Change2Task, um sistema que permite converter alterações em repositórios de código para tarefas executáveis para agentes de codificação, o que é essencial para escalonar esses agentes, pois eles requerem uma grande quantidade de dados para treinamento, benchmarking e avaliação contínua. O Change2Task utiliza a história do repositório para criar tarefas verificáveis a partir de pull requests mesclados, alinhando evidências históricas com o código evoluído. Isso permite a criação de múltiplas tarefas baseadas em evidências de desenvolvedores, fornecendo dados executáveis para agentes de codificação. Com isso, o Change2Task contribui para a expansão da oferta de dados necessários para o treinamento desses agentes.

### [PAIChecker: Uncovering and Checking PR-Issue Misalignment in SWE-Bench-Like Benchmarks](https://arxiv.org/abs/2607.28587v1)
`arXiv`

Pesquisadores descobriram que benchmarks de software, como o SWE-bench, que são usados para avaliar a capacidade de resolução de problemas de modelos de linguagem, muitas vezes contêm pares de solicitações de pull (PR) e issues mal alinhados, o que pode levar a resultados imprecisos. Isso ocorre porque a construção desses benchmarks geralmente envolve a extração de referências de issues das descrições de PR, e a descrição da issue é usada como a declaração do problema, enquanto o patch da PR serve como o teste oracle. Para resolver esse problema, foi proposto o PAIChecker, um sistema multiagente que verifica a consistência desses pares. Esse sistema pode ajudar a garantir a confiabilidade e escalabilidade da construção de benchmarks no futuro.
